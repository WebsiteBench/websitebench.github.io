The agent can use the website but never read its code

/task

Websites combine interfaces, application logic and stored data, and each browser interaction reveals only part of them. A form shows its fields, but only trying it shows which inputs it accepts and whether the new account works later. To rebuild a site, an agent has to choose which pages, actions and states to probe, and then reproduce what it found.

Each task starts from a local reference that an expert built to reproduce selected features of a widely used service. The agent explores it through a browser gateway and writes a full-stack site with pages, back-end logic and persistent data, returning to the reference while it codes and tests, within 16 hours. The submission is then built offline in a separate container and checked by hidden tests. The agent never sees those tests and gets no feedback from the evaluator during the run.

What the agent can use

  • Screenshots and interface state of the reference
  • Navigation, clicks, typing, scrolling and form submissions
  • Images and other media files from the reference
  • Its own email inbox for sign-up and verification flows
  • The task instructions and the runtime contract
  • A shell, build tools and a local browser for its own site

What stays sealed

  • The reference’s HTML, JavaScript and CSS
  • API responses and arbitrary scripts run in the page
  • The server’s source code
  • The hidden tests, reference captures and scores

Three ways the rebuilds go wrong

/findings

We traced 20 Grok 4.6 runs from what the agent observed, to the code it wrote, to the tests it failed. We also compared runs with and without a human exploration trace, and tried a stricter stopping rule on one task. Three failure modes stand out.

1Underexploration

Agents visit nearly every page but finish almost no workflow

Before their first code edit, agents in 17 runs had visited 124 of 127 core page families and started 121 of 122 core workflows. They followed only 4 of those workflows to their final outcome.

A checkout that is never completed, or a review that is never read back, leaves the agent guessing at exactly the behavior the hidden tests check.

Paired test

A human’s exploration trace more than triples the score

On 18 paired websites, the agent also received a read-only log of browser actions recorded by an expert exploring the reference. The log holds actions only, with no page content, so the agent still had to explore for itself.

The mean score rose from 2.8% to 9.8%. The trace helped on 10 sites, tied on 6 and hurt on 2, a significant difference by an exact sign test (p = 0.039). Most of the gain came from sites where the unaided agent passed no tests at all.

2Failure to implement observed behavior

What agents observe rarely reaches their code

Across 20 websites we found 111 requirements that the agent had observed during exploration, with enough evidence to check its implementation: page content, workflows and persistence. One was implemented correctly. The other 110 did not match what the agent had seen.

Effort is lopsided too. More than half of all tool calls explored the reference, and only one in ten edited code.

3Early stopping

Agents stop with most of the clock left

Runs may take 16 hours, yet the median run ended after 3.57 hours. We then enabled Claude Code’s /goal hook for Kimi K3 on the Lowe’s task, so that a review had to accept each attempt to stop.

At 10.25 hours the agent declared its repairs complete. The hook rejected the exit, and the agent went on to check that cart, order, account and session state survived a restart. The score rose from 0% to 31.3%.

What makes a site hard

Deep workflows, more than big sites, are what agents fail to rebuild

We measured each site’s depth, the number of steps in a typical workflow, and its breadth, the number of distinct pages and workflows. Deeper sites scored lower. Among sites with nonzero scores, depth and score are strongly rank-correlated (Spearman ρ = −0.81, p = 0.016). Breadth shows no such link (ρ = −0.14).

More failures the hidden tests caught

  • Medium. The tests found no email input, no verification email was sent, and the session checks that followed failed.
  • Tripadvisor. The review workflow failed at submission, at reading the review back, and again after a restart.
  • Runtime delivery. A build that fails to compile or breaks the runtime contract scores zero on every test.

Three groups of hidden tests

T1

Request

Direct HTTP checks of page responses and native form submissions.

T2

Browser

Scripted journeys through the real interface, at three levels.

  1. L1An immediate response on one page, such as input validation.
  2. L2A state change read back later, such as an edited record on its detail page.
  3. L3Persistence, other users and recovery, such as data after a restart.

Some Browser tests add visual checkpoints that compare screenshots of marked regions with the reference.

T3

System

Runtime requirements: offline builds, restarts, process health and security.

All or nothing, test by test

  • A test earns its point only if its functional checks pass and every visual checkpoint reaches the threshold τ = 0.75.
  • Journey tests must pass under two independent executors, Playwright and Browser Use.
  • Visual similarity is SSIM measured against a flat-color baseline, so large blank areas count for much less.
  • Every test weighs the same and there is no partial credit. A submission that copies the reference scores zero.

Tests that are checked before they count

Every assertion is reviewed with three questions: where could an agent discover this behavior, do the test’s actions actually exercise it, and does the assertion separate success from a plausible wrong implementation. A suite is included only after a complete run against its reference passes every test, and across all 74 tasks two complete reference runs passed every test. Negative controls inject defects such as dead controls, disabled submission, dropped form inputs, state lost on restart and wrong ownership, to check whether the tests catch them.

The runtime contract

Reference and candidate need not share a language or a file layout. What a candidate must honor is a small public contract, so that every submission can be built, started, restarted and probed the same way.

./executable

HOST:PORT
The address to bind, supplied at launch.
GET /healthz
Returns 200 with {"status":"ok"} once the site is ready.

Where all persistent state is written.
SEED, TZ
Fixed randomness and time zone.
SIGTERM
Handled cleanly. Threads are allowed; child processes are not.
Network
None, except explicitly permitted local services.

Questions

/faq
How is the overall score computed?

Every hidden test counts equally, pooled across all 74 sites, so sites with more tests carry more weight. A build that fails to compile or breaks the runtime contract scores zero on every test, and so does an untouched starter project. Trials that fail because of the evaluation infrastructure are excluded instead of scored.

How is visual similarity measured?

A visual checkpoint replays a fixed set of actions in a fresh run, takes a screenshot at a set viewport, and compares marked regions with the reference using SSIM, with masks over parts that should not count. The score is normalized against a flat image in the region’s median color, so plain backgrounds count for little. Every checkpoint of a test must reach 0.75, and a failed checkpoint cannot be averaged away.

Can agents reuse images from the reference?

Yes. The browser gateway lets agents download media files such as product photos, but it filters out JavaScript and CSS and exposes no HTML or API exports. Agents have to rebuild layout and behavior themselves from what they observe, and a submission that copies the reference beyond the permitted media is disqualified.

What does the score measure?

Agreement with the reference behaviors that the hidden tests check, under a fixed observation interface and time budget. The tests are implementation-agnostic, so the candidate need not share the reference’s language or code structure, as long as it honors the runtime contract.

Which agent harness and settings were used?

Every model ran in the same Claude Code harness, version 2.1.268 on Harbor 0.22.0, at maximum reasoning effort, with default sampling settings and a 16-hour wall clock per run.

Will the benchmark be released?

Yes. The paper releases the benchmark, the reference websites, the hidden tests, the evaluation infrastructure and the agent trajectories. Links will appear on this page.
