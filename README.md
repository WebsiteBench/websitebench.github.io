# WebsiteBench project page

The project website for *WebsiteBench: Can AI Agents Rebuild Websites through Browser Exploration?*, hosted at https://website-bench.com/.

WebsiteBench asks agents to explore a reference website through a browser and rebuild it without its source code. This site shows the leaderboard for the 70 released tasks, a task browser, analysis pages and the commands to run the benchmark. The benchmark code is at [TIGER-AI-Lab/WebsiteBench](https://github.com/TIGER-AI-Lab/WebsiteBench), and the tasks are on [Hugging Face](https://huggingface.co/datasets/TIGER-Lab/WebsiteBench) and [Harbor Hub](https://hub.harborframework.com/datasets/websitebench/WebsiteBench).

The site is static and has no build step. The homepage, the leaderboard table and the CSV downloads work without JavaScript; scripts add sorting, the Pareto and Waffle views, the task demo and the failure tree's lines, theme selection, copy buttons and the task browser.

## Results

All views use the same results for the 70 tasks and eight models.

- Scores are test-pooled pass rates: 100 × sum(passed tests) / sum(total tests), for Overall and for each test group (Request, Browser and System).
- Cost, tokens and turns are means over the tasks with recorded values. Each Pareto point plots the model's Table values.

| File | Content |
| --- | --- |
| `data/cohort.json` | The 70 tasks and eight models |
| `data/leaderboard-views.json` | Aggregates; `data/leaderboard.json` holds the same list |
| `data/waffle.json` | Per-task results for every model |
| `data/leaderboard*.csv`, `data/waffle-*.csv` | CSV exports of the same numbers |
| `data/task-materials.json` | Task browser catalog: recorded runs and their published scores |
| `data/task-previews.json`, `assets/previews/` | Screenshots of each task's reference and of each run's rebuild, by page |
| `data/demo-task.json`, `assets/previews/ubereats/` | The Uber Eats run in the homepage demo: pages, paired screenshots, differences and hidden test results |
| `data/analysis.json` | The Lowe’s continuation case shown on the homepage and the Analysis page |
| `data/evaluated-tasks.json`, `data/task-catalog.json` | Generated by `tools/prerender.js` |

Do not edit aggregate percentages or the CSV exports by hand.

## Maintenance

```sh
node tools/prerender.js
node tools/render-og.js
python3 -m unittest discover -s tools -p 'test_*.py'
```

- `tools/prerender.js` checks that the leaderboard and the per-task results agree on every test count. It then writes into `index.html` the leaderboard rows, the inline data, the BibTeX block, the list of released websites and every number marked `data-fact` (task, test and model counts, the best score and its turns per task, tests per task and their range), and the demo's tabs, test rows and data. It also rewrites the leaderboard block of `llms.txt` and regenerates `data/evaluated-tasks.json` and `data/task-catalog.json`. Run it after any change to `data/` or `CITATION.bib`.
- `tools/render-og.js` redraws the social card `assets/og.png` from `tools/og.html`. It needs Playwright; set `PLAYWRIGHT` to use an existing installation and `CHROMIUM_PATH` to use an existing browser.
- The tests check that every page, data file and export covers the same 70 tasks and that the published numbers agree.

`CITATION.bib` is the source of the homepage BibTeX block. Update it together with `CITATION.cff`.

## Deploy on GitHub Pages

In **Settings → Pages**, choose **Deploy from a branch**, branch `main`, folder `/ (root)`. The `.nojekyll` file stops GitHub from running Jekyll.
